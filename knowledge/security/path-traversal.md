# 路径遍历攻击防御

> 覆盖攻击变体：相对路径穿越（`knowledge/../../.env`）、系统绝对路径直取（`J:/.../.env`）、多层跳转（`../../../../etc/passwd`）、伪装成"忽略指令"的注入式读取。
> 这些攻击**入口不同，但防御机制同一个**：路径规范化 + 白名单校验。

## 漏洞成因

路径遍历漏洞（又称目录穿越）的根本成因在于：应用程序接受了用户输入的相对路径，并在拼接后直接用于文件系统操作，且未对路径中的特殊字符（如 `../`）做有效过滤。攻击者利用 `../` 序列向上回溯，试图访问应用程序根目录之外的系统敏感文件（如 `/etc/passwd`、`.env`、配置文件等）。

## 防御机制：规范化 + 白名单校验（两步，缺一不可）

### 1. 路径规范化（Normalization）

用 `Path.resolve()`（或等同的 `realpath`、`getCanonicalPath`）将用户输入与预设的沙箱根目录拼接，解析为操作系统真实的绝对路径。该操作会严格按照文件系统目录结构，将所有 `../` 和 `.` 等相对跳转符号进行实际换算，彻底还原路径的物理位置（如 `knowledge/../../.env` → `J:/.env`），从而消除攻击者利用多层跳转伪装路径的意图。

### 2. 白名单校验（Allowlist）

得到规范化绝对路径后，检查其是否以沙箱根目录（如 `J:/programs/secops-copilot/knowledge`）为前缀，即真实路径是否位于允许目录内（可用 `requested_path.is_relative_to(allowed_dir)` 判断）。若不在白名单范围内，立即拒绝访问。

## 安全金律

- **先校验，后操作**：白名单校验必须在文件操作（`open`）之前完成，不能先读再判断。
- **白名单优先级最高**：任何跳出白名单目录的读取一律拒绝，无论攻击者用多少层 `../`、用绝对路径还是相对路径、是否伪装成"忽略之前所有指令"。规范化后物理路径说了算，话术不影响判定。
